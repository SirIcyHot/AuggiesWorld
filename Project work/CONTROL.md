## Where control lives in PharmaPy

**The ConcurrentVessel itself has no controllers.** It is a coordinator: it
puts all its members on one integrator, keeps their states in sync, and
passes on each member's own controller states and switching events. The
control is on each member: every `MultiPhaseVessel` owns exactly one
`controller` from `PharmaPy/ProcessControl_Refactored.py`.

What the ConcurrentVessel adds for control:

- **Cross-unit measurements.** Before any balance is evaluated, every member
  is updated to the current state (`sync_members=True`, the default). A
  member's controller may therefore hold a reference to another member and
  read its state, e.g. trim CR02R's feed from a concentration measured in
  D01R. Each member still has exactly one controller; it only observes its
  neighbour. In a sequential `SimulationExec` flowsheet this is impossible,
  because the downstream unit hasn't been solved yet.
- **Controller states integrated with the plant.** Controller memory is
  declared as solver states, so the ConcurrentVessel integrates and replays
  it along with every member.
- **Controller events.** The ConcurrentVessel gathers every member's
  switching surfaces (for example the level loop's no-backflow floor) into
  one root-finding problem (`compile_events` / `handle_event`).
- **Recycles with level control.** A level controller makes outlet flow
  depend on inlet flow, which is what makes a recycle algebraic. The
  ConcurrentVessel closes such loops either by iterating (`tear_mode='iterate'`,
  Wegstein) or as algebraic states (`'algebraic'`, which needs a DAE backend).

### How a controller is called

On every right-hand-side evaluation the vessel calls its controller twice
(`MultiPhaseVessel.get_operating_conditions`):

1. `observe` → `compute_operating_conditions` → `actuate` with the vessel
   state only. This sets anything that doesn't depend on the feed: the
   jacket temperature and inlet overrides.
2. The same again with the resolved inlets. This sets the outlet flow, which
   is trimmed around the actual feed.

`actuate` writes **operating conditions** (the manipulated variables):

| OperatingKey | Manipulates |
|---|---|
| `OperatingKey("vol_flow", connection=0, port="outlet")` | outlet flow |
| `MultiPhaseVessel.UTILITY_TEMPERATURE` (`"temp_in"`, port `"utility"`) | jacket inlet temperature (overrides `Utility.temp_in`) |
| `OperatingKey(name, connection=i, phaseref=..., port="inlet")` | an inlet field (flow, temperature, ...) |

A controller can also **own a state** outright: putting `global_temp` in
`controller.states` replaces the energy balance with a prescribed
temperature (`TemperatureProfileMixin`).

**Memory is solver states, not attributes.** A PI integral or a filtered
measurement is declared as a `StateVariable` (`solver_states`), and its rate
is returned by `get_solver_state_rates`. So it is integrated only along the
accepted trajectory, replayed exactly, and carried through the
ConcurrentVessel. An attribute updated inside `actuate` would instead pile up
over every trial point the integrator evaluates.

| `ContinuousVesselController` | P level + T imposed | |

| `PIDTemperatureController` | PI(D) T through the jacket | keeps the energy balance; needs a `Utility` |

### Level loop (P, the default)

```
F_out = F_in + K (V − V_set),     K = 1 / tau,   tau = 0.01 × residence time
```

The flow is passed through a smooth (C1) floor so it never goes below zero.
The volume error decays with time constant 1/K. The default gain is set from
a settling time (a hundredth of a residence time), not given directly, so the
loop is equally tight on any vessel size without making the model needlessly
stiff. A `StateEvent` marks where the requested flow crosses zero.

**The P loop has an offset** whenever the outflow has to differ from the
inflow at steady state (the liquid gets denser as it reacts, or the slurry
carries crystals out). The level then settles at `(F_out − F_in) / K`
from target. In R02R this offset is −8.8 mL: 1023 vs 1035 mL/min, with
K = 1/44 s.

### PID loops (`PIDLoop`)

ISA (standard) form, around a bias:

```
u = bias + Kc (e + I/Ti + Td s dy_f/dt),     e = s (y − y_set)
dI/dt = e + Ti / (Kc Tt) (u_applied − u)        (back-calculation anti-windup)
dy_f/dt = (y − y_f) / Tf                         (filtered measurement for D)
```

- `s = +1` is direct action (level: more volume means more outflow) and
  `s = −1` is reverse action (temperature: too cold means a hotter jacket).
- Derivative action uses the filtered measurement, so a set-point step
  doesn't kick the output (no derivative kick).
- Anti-windup pulls the integral back while the applied output differs from
  what the law asks for, e.g. at a jacket limit or when the no-backflow floor
  throttles the outlet. `Tt` defaults to `Ti`.
- Integral and filter states are named `<loop>_integral` and
  `<loop>_filtered`, and appear on `vessel.result`.

**Default tuning**
- *Level:* `Kc = 1/(0.01 τ_res)`; `Ti = 4/Kc`. The level is an integrating
  process, so with `e'' + Kc e' + (Kc/Ti) e = 0` this choice gives critical
  damping.
- *Temperature (jacket):* this is IMC tuning for a first-order process.
  - The jacket time constant is `τ_ht = m cp / (U A)`, taken from the vessel
    at its first evaluation.
  - `Ti = τ_ht`.
  - `Kc = 1 / closed_loop_fraction`, which is 4 by default, so the
    closed-loop time constant is λ = τ_ht/4.
  - The set point is the bias, so with no other heat load the loop needs no
    integral.
- For R02R, τ_res ≈ 74 min and τ_ht ≈ 217 s.

## Gotcha: swapping a controller after the vessel is built

The controller's states are registered in `define_solver_states`, which runs
when the vessel's phases (or phase connections) are set. If you assign
`vessel.controller = PIDContinuousVesselVolume()` afterwards, nothing warns
you: the integral is never registered, and the PI loop silently runs as P
only. (Seen here: T settled at 60.88 °C instead of 60.) The same applies to
an imposed-temperature controller, which has to remove `global_temp` from the
solver states.

Either pass `controller=` to the vessel's constructor, or re-lay the states
afterwards, as `R02R_control.install_controller` does:

```python
vessel.controller = controller
vessel.solver_state_collection = StateCollection()
vessel.output_state_collection = StateCollection()
vessel.nomenclature()
```

## Results

### R02R (10 h, set point 60 → 55 °C at 5 h)

| Mode | Controller | T at end | Level offset | T step: offset / overshoot / 2 % settling |
|---|---|---|---|---|
| `open` | P level, jacket fixed at 60 °C (PharmaPy default) | 64.44 °C | −8.81 mL | not tracked |
| `pi` | PI level, jacket fixed at 60 °C | 64.44 °C | 0.00 mL | not tracked |
| `jacket` | PI level + PI jacket T | 55.00 °C | 0.00 mL | 0.000 K / 8.8 % / 10.0 min |
| `imposed` | PI level + T imposed | 55.00 °C | 0.00 mL | exact (bound) |

- **Open loop:** the reaction heat holds the vessel 4.4 K above the jacket.
- **Jacket loop:** about 5 K below the set point is needed to remove the
  reaction heat: the jacket sits at 55.4 °C for a 60 °C set point and at
  50.0 °C for 55 °C. At the step the jacket briefly drops to 30 °C, which is
  well inside the 5–95 °C limits, so anti-windup never engages.

### CR02R (10 h, set point 60 → 55 °C at 5 h; `results/control/run_compare.log`)

| Mode | T at end | Level offset | T step: offset / overshoot / 2 % settling | Wall time |
|---|---|---|---|---|
| `open` (PharmaPy default) | 59.78 °C | −2.56 mL | not tracked | 25.6 min |
| `pi` | 59.78 °C | 0.00 mL | not tracked | 29.7 min |
| `jacket` | 55.00 °C | 0.00 mL | 0.000 K / 9.0 % / 10.0 min | 27.2 min |
| `imposed` | 55.00 °C | 0.00 mL | exact (bound) | 24.0 min |

- **Open loop CR02R sits close to its jacket** (0.2 K below), unlike R02R,
  which runs 4.4 K hot. The jacket loop therefore holds the jacket near the
  set point: 60.2 °C for a 60 °C set point and 55.0 °C for 55 °C. At the step
  the jacket dips to 35 °C.
- **The temperature loop behaves almost the same as on R02R** (9.0 % vs 8.8 %
  overshoot, 10 min settling), because the default tuning is set from the
  jacket's heat-transfer time constant.
- **The level offset is smaller** (−2.6 mL against −8.8 mL), since outflow
  and inflow differ less (980 vs 983 mL/min).
- **The small level and flow bumps at about 2.7 h and 3.7 h appear in every
  mode,** so they come from the process, not the loops. They look like
  nucleation starting for a product species. The step at 5 h briefly upsets
  the level by up to 1.6 mL, which the PI loops remove within minutes.

### CR02R plant model (`CR02R_control_theory.ipynb`)

Plant: jacket inlet temperature → vessel temperature, at the 60 °C / 6 h
operating point, with the PI level loop on.

- **Fitted G(s):** `0.958 / (201 s + 1)`. There is no dead time (the fitted
  delay is 0.06 s), and SOPDT gives no evidence of a second lag. A lead-lag
  fit adds a nearly cancelling pole and zero at about 5100 s (about 0.1 %
  of the gain). Every fit is within 0.2–0.8 mK on the 2 K identification
  step and about 5 mK on the −4 K validation step. That 5 mK is the
  plant's nonlinearity: the gain is 0.9587 on the +2 K step and 0.9571 on
  the −4 K step.
- **Cross-checks on τ:**
  - first principles, K·m cp/(UA): 208 s
  - the temperature row of the Jacobian, −1/A_TT: 200.4 s
  - the dominant PBH mode of the full model: 200.5 s
  - the full model's DC gain: 0.957
- **Full linearization (818 states):** all modes the jacket can excite or
  the temperature can see are stable. Nine eigenvalues have a slightly
  positive real part (doubling times 26–85 min). They sit at the leading
  edge of the D, E and J size distributions, and their PBH measure is
  about 1e-7 of the temperature mode's. They come from the not-quite-steady
  point and the van Leer flux limiter, and feedback through T cannot move
  them. The matrix is strongly non-normal (cond(V) ≈ 1e31), so the modal
  residue split is meaningless; the notebook uses the PBH test instead.
- **PharmaPy default PI (Kc = 4, Ti = 217 s) is IMC tuning.** The PI zero
  cancels the plant pole, so L ≈ ωc/s with ωc = 0.019 rad/s. That gives
  PM = 91°, GM = ∞, Ms = 1.00 and an 84 s delay margin. The 9 % overshoot
  comes from the set point entering as the bias (feedforward). The linear
  prediction matches the nonlinear closed-loop run: 8.9 % overshoot and
  10 min settling for both.
- **Crystal yield:** the jacket-to-yield plant is slow (time constant
  ~1–1.5 h). For D it is non-minimum phase, with an inverse response
  (a right-half-plane zero at 1/1890 s). D is the only product whose
  reaction speeds up with temperature.

### R02R state-space control (`R02R_state_space.ipynb`)

Plant: jacket inlet u → vessel T, feed temperature d as the disturbance,
linearized at the steady state (jacket 60 °C, feed 30 °C, T0 = 64.44 °C)
with the PI level loop on. The state is PharmaPy's own: 12 species masses,
T and the level integral (14). B, C, K and L are never present and are
dropped, leaving 10.

- **Steady state:** a 10 h run, then Newton on `unit_model`: |f| from 4e-6
  to 2e-16 in two steps, so the LTI model has no constant term.
- **LTI accuracy:** 0.2 mK worst error on a +2 K jacket step (T moves
  1.9 K) and 0.4 mK on a +20 K feed step; the compositions drift a few
  percent from the LTI model over hours. dT/du = 0.951, dT/dd = 0.043.
  This needs explicit tolerances (`rtol` 1e-8, `atol` 1e-10): on Assimulo's
  defaults the same check showed ~1.5 mK, nearly all integration error.
- **Modes (all stable):** F's turnover 1.0 s (the starved reactant), the
  PI level loop 88 s (a critically damped double pole), the temperature
  199 s (m cp/UA = 209 s), and six wash-out modes at the residence time
  (4470 s).
- **Controllability/observability:** numerically 5 of 10 directions
  controllable and 4 observable. Only the temperature mode is strongly
  both (PBH 1.0 / 0.95). About six independent eigenvectors share 1/τ, so
  one input cannot control them (PBH corollary): the jacket only moves the
  three reaction rates. Stabilizable and detectable.
- **Transfer function, derived:** 10 poles, 9 zeros, all but one cancelling
  (F's mode to 1e-10, the level pair 0.7 %, wash-out 0.3 %), so
  G(s) ≈ 0.95/(199 s + 1). Hankel σ2/σ1 = 1.5e-3; the r = 1 balanced model
  is 0.952/(199 s + 1). (CR02R's fitted G(s): 0.958/(201 s + 1).)
- **Pole placement** on the r = 2 model: moving the weakly controllable slow
  pole costs 7–30 K of jacket per K of set point (gains up to ~1700).
  Leaving it in place gives 1.1–1.9 K for τ_cl = 300–60 s.
- **LQI** (q_T = 1, q_z = 1/60², r_u = 0.05, scaled): t63 = 108 s, overshoot
  0.08 %, jacket peak 1.9× the step. Only the temperature mode moves, to
  −0.017 ± 0.008j.
- **Kalman filter on T alone** (σ_d = 2 K, σ_y = 0.05 K): cuts T's
  uncertainty to 0.62 and leaves every mass at 1.00 — the masses are
  estimated by running the model, not by measurement. An unmeasured
  20 K feed step biases the plain filter (reactant estimates off by ~97 %
  of their move); with the feed temperature as an extra filter state
  (random walk 0.05 K/√s) the bias goes (a few % of each move) and d̂
  recovers the feed temperature to 0.01 K.
- **Robustness (loop broken at the plant input):**

| Loop | PM | GM | Ms | Delay margin |
|---|---|---|---|---|
| LQR (full state) | 78° | ∞ | 1.00 | 44 s |
| LQG | 60° | ∞ | 1.25 | 61 s |
| LQG + disturbance estimate | 51° | ∞ | 1.33 | 45 s |
| PharmaPy PI (Kc 4, Ti 209 s) | 91° | ∞ | 1.00 | 83 s |

- **Nonlinear runs in PharmaPy** (set point −2 K at 0.25 h, feed +20 K at
  2.5 h; `LQGController` integrates its observer as solver states):

| Controller | Overshoot | 2 % settling | Jacket move | Disturbance peak / IAE | NL − linear |
|---|---|---|---|---|---|
| PharmaPy PI | 9.2 % | 9.7 min | 10.0 K | 0.141 K / 47.2 K s | 0.04 mK |
| LQG | 0.1 % | 4.3 min | 3.8 K | 0.171 K / 28.8 K s | 0.06 mK |
| LQG + disturbance estimate | 0.1 % | 4.3 min | 3.8 K | 0.149 K / 23.1 K s | 0.06 mK |

  Each 5 h run takes 5–7 s.

## Gotcha: give AssimuloBackend explicit tolerances

`AssimuloBackend()` with no options ran R02R ~35× slower than
`AssimuloBackend(options=dict(rtol=1e-6, atol=1e-8))` (33 s against 0.9 s
for 3 h), and its answers were *less* accurate: ~1.5 mK of integration
error in the LTI check above, against 0.2 mK at `rtol` 1e-8 / `atol` 1e-10,
which still runs in seconds. The feed-temperature inlet override costs
nothing measurable. `R02R_control.py` and `R02R_state_space.py` both pass
options; `CR02R_control.py` and `CR02R_plant_id.py` use the defaults
(`SOLVER_OPTIONS = None`), which may be part of why CR02R takes 25–35 min.

## Gotcha: PharmaPy's right-hand side returns a reused buffer

`MultiPhaseVessel.unit_model(t, x)` returns an array that it overwrites on
the next call. Finite differences such as `f(x + h) - f(x - h)` then
subtract the array from itself and give an all-zero Jacobian, with no
error. Copy every result: `np.array(vessel.unit_model(t, x), copy=True)`.

## Gotcha: a custom controller's attribute names can clobber PharmaPy's

A controller that subclasses a level controller inherits its attributes.
`DefaultContinuousVesselVolume.get_gain` returns `self.K` when it is set (an
explicit level gain), so storing an LQR gain as `self.K` silently made the
outlet flow an array. The vessel failed far away, in `_resolve_outlets`
("operands could not be broadcast"). `LQGController` prefixes its own
attributes (`lqg_K`, `lqg_A`, ...). Check the parent classes before naming
attributes `K`, `tau`, `target_volume`, `integral_time`, and so on.

## Ideas for next studies

- **Disturbance rejection:** step the feed flow or composition (a
  `DynamicInlet` feed) rather than the set point.
- **Cross-unit control:** `CR02R_D01R.py` now has CR02R and D01R in one
  ConcurrentVessel. Next, a controller on CR02R that reads D01R (its
  supersaturation or crystal inventory) through `sync_members`.
- **Feedforward from the disturbance estimate:** `LQGController` with
  `disturbance=True` estimates the feed temperature but does not use it;
  `u_ff = -G_u(0)^-1 G_d(0) d_hat` would cancel it before T moves.
- **A composition measurement:** a second row in C (an outlet analyser)
  would make R02R's products observable; compare the Kalman covariances.
- **Tuning sweeps:** `closed_loop_fraction`, `tau` and `integral_time` against
  IAE, overshoot and jacket effort.
- **Actuator limits:** narrow `JACKET_LIMITS` until the anti-windup is
  active, and compare with `tracking_time` very large (effectively no
  anti-windup).
